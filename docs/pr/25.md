# Fix 25: verify and resync the old internal meta-data range after an "--assume-clean" grow (opt-in)

Upstream report: LINBIT/drbd#165 (a DRBD-side fix would make this unnecessary). Base: v3-r7b (413c914aa).

## Problem
For thinly backed volumes LINSTOR grows the DRBD device online with `drbdadm resize --assume-clean` (DrbdLayer, the "needsResize" loop).
- With internal meta-data, DRBD 9.3.4 moves the meta-data to the new end of the device and leaves the old range (superblock, activity log, bitmap) in the data area.
- That range is neither zeroed nor marked out of sync (`DDSF_NO_RESYNC` → `drbd_bm_resize(set_new_bits = false)`), so each node keeps its own old bytes there.
- `drbdadm verify` then reports one 4 KiB out-of-sync block per grown resource, and a diskless Primary reading that range gets A's and B's version in turn.
- Seen on our dev cluster: a clone grown from 10 GB to 40 GB on 2026-11-05.

## Fix
Opt-in with `LINSTOR_SATELLITE_RESYNC_OLD_MD_AFTER_GROW=true`. After an `--assume-clean` grow of a volume with internal meta-data on a diskful node (new class `OldInternalMdResync`):
1. Read the DRBD device size before and after the resize (`blockdev --getsize64`).
2. Compute the old meta-data range: `[old size, old size + meta-data size + 1 MiB)`, clamped to the new size.
   - The meta-data size comes from `MetaData.getGrossSize` with LINSTOR's layout (1 AL stripe of 32 KiB) and the smallest bitmap block size (4 KiB), i.e. the largest bitmap, so any bitmap block size is covered.
3. Pick the peers: the diskful, not-deleting peers with a higher node-id, so exactly one side of each pair acts (`DrbdLayer.oldMdResyncPeers`). Of those, only peers that are `Established`, `UpToDate` and have 0 out-of-sync in `drbdsetup status --json` are verified. The out-of-sync count is volume-wide, so a peer that is already catching up is left alone.
4. Run `drbdsetup verify <res> <peer-node-id> <vol> --start=<KiB>k --stop=<KiB>k` per peer. drbdsetup takes the context positionally: resource, peer node-id, volume.
5. Poll `drbdsetup status --json` until no verified peer is in `Verify*`, for at most 10 s. Starting a verify is a synchronous state change, so a first poll without `Verify*` means it has already finished.
6. For a peer with out-of-sync > 0, run `drbdsetup disconnect <res> <peer-node-id>`. The `drbdadm adjust` that the resize already requires reconnects it, and the marked blocks resync, in either direction: neither side's old meta-data is guest data.

Every failure (sizes, status, verify, timeout) is logged as a warning and ignored; the grow itself is never affected.

## Cost and risk
- Per grow: a verify of about 2-3 MB per diskful pair (milliseconds) and, only if differences are found, one short reconnect of that peer. The volume's creation time is about unchanged.
- The disconnect briefly drops one replication link. With 2 diskful nodes and a diskless member, both sides keep quorum through the diskless member. A Primary on the verifying node would see protocol C writes wait during the reconnect.
- The DeviceManager run can wait up to 10 s per grown volume if a verify does not finish (normally milliseconds).
- If a verify is already running on that resource, ours fails and is only logged.

## Review (Qwen adversarial pass, checked here)
- **Not real:**
  - "drbdsetup verify/disconnect take the peer as an option": the context is positional (drbd-utils drbdsetup.c `next_arg` loop).
  - "premature done": `start_ov` is a synchronous state change.
  - "peers not resized yet": DRBD 9 resize is cluster-wide (2PC).
  - "AL striping": LINSTOR creates internal meta-data with the default 1 stripe of 32 KiB.
- **Real, fixed:**
  - out-of-sync is volume-wide → pre-check for 0 and Established/UpToDate;
  - the range could exceed the new size on small grows → clamped;
  - the tests pinned the exact `--stop` value too loosely, and the superblock position was recomputed → now pinned exactly, and taken from the incident's sector;
  - the wait was lowered from 30 s to 10 s.

## Tests
- `OldInternalMdResyncTest` (7):
  - the range covers the incident's superblock (sector 20976088) and is bounded;
  - clamping to the new size;
  - verify per peer with exact arguments, and disconnect of only the differing peer;
  - a peer with pending out-of-sync is not verified;
  - a failed verify is not disconnected;
  - a verify that never finishes disconnects nothing;
  - no peers or no growth runs nothing.
- `DrbdLayerOldMdResyncPeersTest` (2): only diskful, not-deleting peers with a higher node-id; the highest node-id verifies nothing.
- Full module runs: see the build report.
