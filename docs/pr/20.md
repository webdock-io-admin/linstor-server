# Fix 20: skip the no-op drbdmeta set-gi calls for new volumes

## Problem

For every new DRBD volume with metadata to initialise, `DrbdLayer.createMetaData()` runs `drbdmeta --force --node-id <N> <minor> v09 <dev> internal|flex-external set-gi <gi>` once for every node-id 0..31 (`NodeId.NODE_ID_MAX`). That is 32 sequential execs per volume. On the dev rack, at ~940 datasets per storage node, each exec took ~156 ms (p50), so about 5 s per volume. That was about half of the satellite's exec time during a create ramp: 3,200 set-gi calls per 100 creates.

## Cause

`DrbdLayer.java`, `createMetaData()`, the loop after `if (runSetGi)` (master e1d99946e / v1.35.3: lines 1597-1606). There are two branches that set `runSetGi`:

- **Local satellite won the UpToDate race.** The other node-ids get `withBitmapBaseDataUUID(day0)`. The bitmap UUID is stored per peer slot (`peers[node_id].bitmap_uuid` in drbdmeta), so each node-id needs its own call.
- **Skip initial sync** (`DrbdLayerUtils.skipInitSync()`). The other node-ids get only `withCurrentUUID(day0)`, which renders as `<day0>:::::`.

In drbd-utils 9.35.0, `m_set_v9_uuid()` stores the current UUID, the history UUIDs and the device flags device-wide. Only the bitmap UUID and the peer flags go into `peers[node_id]`. Empty fields leave the stored value unchanged (`m_strsep_u64()`, `m_strsep_u32()` and `m_strsep_bit()` all check `strlen(t)`). `meta_set_gi()` does nothing else per node-id: open, apply, write the whole metadata, close. So in the skip-init-sync branch, the 31 calls for the other node-ids write the same current UUID that the local call writes, and nothing else.

## Fix

- `DrbdGiStringBuilder.hasPeerSlotData()` returns true if the GI sets a per-slot field: the bitmap UUID or the peer-outdated bit. These are the only per-slot values the builder can emit.
- `createMetaData()` runs set-gi for the other node-ids only if `otherNodeIdGiBuilder.hasPeerSlotData()`. The local node-id always gets its call.
- Effect: the UpToDate-race-winner branch keeps all 32 calls. The skip-init-sync branch runs one call.

The end state of the metadata is unchanged. One difference: if the local set-gi fails, the node-ids below it have not already written the current UUID. The volume creation fails with a `VolumeException` either way.

## Tests run

- New unit tests in `DrbdGiStringBuilderTest`: `currentUuidOnlyHasNoPeerSlotData`, `bitmapUuidIsPeerSlotData`, `peerOutdatedFlagIsPeerSlotData`.
- `./gradlew :satellite:test`: 139 tests, 0 failures. `./gradlew :test`: 2,253 tests, 0 failures. `:satellite:checkstyleMain` is clean.

- Adversarial review: Qwen first pass, then each point checked against the code. One follow-up: a comment requiring future per-slot setters to extend `hasPeerSlotData()`.
