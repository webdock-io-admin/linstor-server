Title: REST: return the ApiCallRc list for errors of resource-definition clone

Branch: webdock-io-admin/linstor-server `fix/linstor-server-560-clone-error-body`, on master e1d99946e.

---

Fixes #560. Related: LINBIT/golinstor#22 (client-side workaround, now a draft at the maintainer's request).

**Problem.** `POST /v1/resource-definitions/{rsc}/clone` answers a failed clone with HTTP 500 and a `ResourceDefinitionCloneStarted` object (`{location, source_name, clone_name, messages}`). Every other endpoint returns an `ApiCallRc` list. Clients that decode error bodies as a list, golinstor among them, lose the controller's message and report only "json: cannot unmarshal object into Go value of type client.ApiCallError". The OpenAPI spec documents a third shape for this 500, `OperationFailed`, which is a single `ApiCallRc`.

**Change.**
- `ResourceDefinitions.mapToCloneStarted()` delegates to a new `cloneStartedResponse()`:
  - On errors it returns `ApiCallRcRestUtils.toResponse(...)`, the same helper and body as the other endpoints. The status follows the error codes as elsewhere: 500 in general, 404 for a missing object, and 403/401 for authorization failures.
  - On success the response is unchanged: 201 with the `ResourceDefinitionCloneStarted` object.
- An unparsable request body now gets the usual 400 `ApiCallRc` list (`handleJsonParseException`). Before, the catch-all only reported the exception and never resumed the async response, so the client got no answer.
- OpenAPI: clone `404` and `500` are documented as `ApiCallRcList`. CHANGELOG and CHANGELOG-OPENAPI have entries.

Not changed: the shared `OperationFailed` response, which other operations reference and which also says single `ApiCallRc` (point 2 of #560), and the two other non-list error bodies listed in #560. Glad to follow up on those if wanted.

**Compatibility.** Since 9d96b8001 (2025-09), clone errors have been a 500 with the object. A client that reads `.messages` from that object on errors needs to read the list instead.

**Tests.**
- New `ResourceDefinitionsCloneResponseTest` (5): an error gives a 500 list; not-found gives a 404 list; info entries followed by an error give a list of all entries; success gives the 201 object; no entries gives the 201 object.
- `./gradlew :controller:test` (104) and `./gradlew :test` (2,253) pass. `:controller:checkstyleMain` and `:controller:checkstyleTest` have no new warnings.
