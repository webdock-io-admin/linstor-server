# Fix 21: scope the satellite's per-run DRBD calls to the resources it acts on

Base: v1.35.3 + fix 16 (#561) + #545 (#554) + fix 20, i.e. the `dev-16-jars-1.35.3-v3-r2` code.

## Problem
After fix 16, a storage satellite's DeviceManager run is spent mostly in whole-node DRBD tool calls. Measured on our dev cluster at ~1,000 resource definitions, per run: `drbdadm` 0.50 s (`sh-list-adjustable all` plus `adjust`), `drbdsetup status` 0.27 s, `zfs` 0.17 s, ~0.4 s Java. At 2,005 resource definitions a run takes ~1.9-2.2 s. See LINBIT/linstor-server#565 and #568.

## Cause (v1.35.3)
- `DrbdLayer.prepare()` ran a whole-node `drbdsetup status` every run (`DrbdLayer.java` :170-173). Its only consumer, `needsNewMetaData()` (:1154), looked for one resource's "role:" line.
- `drbdadm sh-list-adjustable all` (`DrbdAdm.java` :646) and every `drbdadm -vvv adjust <rsc>` (:104) parse /etc/drbd.conf, i.e. every file in /var/lib/linstor.d. The code says so itself: "drbdadm will read all files anyway" (:645), and "-c" was avoided because it drops global_common.conf (:106).

## Fix
1. `needsNewMetaData()` checks the rare flag combination (not INITIALIZED, FORCE_NEW_METADATA) first. Only then does it run `drbdsetup status <rsc>` for that one resource; that per-resource call already existed as the fallback. The whole-node call is gone. Same semantics: a resource line in `drbdsetup status` carries "role:" exactly when the resource exists in the kernel.
2. `DrbdAdmScopedConf` writes a temporary config that includes /etc/drbd.d/global_common.conf plus only the given .res files. `sh-list-adjustable` (for the resources dispatched in this run) and `adjust <rsc>` run with `-c <that file>`. The file is deleted after the call; leftovers from a crash are deleted at the first scoped call.
3. Scoping is used only on Linux and only on the standard layout. That means /etc/drbd.conf has exactly `include "drbd.d/global_common.conf"; include "drbd.d/*.res";` (relative or /etc-absolute), and the only .res file in /etc/drbd.d is linstor-resources.res. Anything else, a missing .res file, or a failure to write the file keeps the old unscoped call. Falling back logs a warning once.

Not changed: other drbdadm calls (resize, down, ...) and the controller's rd-wide re-dispatch of resources on every attach/detach. The latter is item 4, a controller change for later.

## Risk
- Cross-file checks that drbdadm does over the whole config (duplicate minor or port) are not done in scoped calls. LINSTOR allocates those.
- Any site config beyond the standard layout is detected and makes the satellite fall back to the old behaviour.

- `DrbdAdmScopedConfDrbdadmTest` (2): runs a real drbdadm 9.35.0, built from the v9.35.0 tag, through `LINSTOR_TEST_DRBDADM` (skipped if unset). For three sample LINSTOR-style .res files, `drbdadm dump <rsc>` and the dry-run `drbdadm -d up <rsc>` (the full drbdsetup command list with merged common options) are identical with the full config and with the scoped one. A common-section option in global_common.conf reaches the scoped call.

## Not run here
- `drbdadm -d adjust` needs a DRBD kernel module, which this machine does not have. On a storage node, run the check below before and after the swap.

Node check (read-only, prints DIFF for any resource whose dry-run adjust differs):

    for r in /var/lib/linstor.d/*.res; do n=$(basename "$r" .res); \
      printf 'include "/etc/drbd.d/global_common.conf";\ninclude "%s";\n' "$r" > /tmp/scoped.conf; \
      diff -q <(drbdadm -d adjust "$n" 2>&1) <(drbdadm -c /tmp/scoped.conf -d adjust "$n" 2>&1) >/dev/null || echo "DIFF $n"; \
    done; rm -f /tmp/scoped.conf
